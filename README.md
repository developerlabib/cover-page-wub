# Cover Page for WUB Students

Version 1.1.0: a complete, English-only assignment studio created from the supplied nine-page **Assignment Cover Page Blank.docx**. The original artwork, university logo, headings and tables are retained. All form values are drawn as sharp PDF text over the original design.

## Included features

- Nine selectable templates in the same sequence as the Word file.
- Editable degree, topic, course title/code, submission date, student details and teacher details.
- Optional **Assignment No** above Topic, with one-click on/off control. The original font, 18 pt label size and colon alignment are retained on every design. Switching off hides the entire row without discarding its number.
- Live preview generated by the same PDF engine used for downloads.
- Download a single A4 cover PDF or a 200 DPI PNG.
- Add JPG, PNG, WebP or existing PDFs. PDF uploads are separated into individual pages.
- Move, rotate and remove individual pages; the cover always stays first.
- Preview every page of the assembled assignment before downloading.
- Every exported page is A4 portrait, 210 × 297 mm, with proportional fitting and no cropping.
- Original, Balanced and Compact quality choices. Original preserves attached PDF text; the other modes rasterize attachments for smaller scanned documents. Compression savings depend on the input.
- Automatic local draft saving, plus optional authenticated Realtime Database draft backup.
- Browser-only file processing. **Firebase Storage, Cloud Functions and a server are not required.**
- Redesigned phone, tablet and desktop layouts with three clear steps, large input fields and a fixed phone action bar. Phone previews open in a separate panel with PDF/PNG download controls.
- Developer footer: **MD. Labib Hasan**, with configurable photo, WhatsApp and Facebook links. Developer details are never added to the exported pages.

## Run locally

Install a current Node.js LTS release (Node 20 or newer). Extract the ZIP, open this folder in VS Code, and open its terminal:

```bash
npm run dev
```

Open `http://localhost:3000`. Do not open `index.html` by double-clicking: modules and PDF loading require a local web server.

There are no npm application dependencies to install. The PDF libraries, worker, fonts and template artwork are bundled locally. Their licenses are in `web/vendor/`.

## Deploy to your Firebase project

The included `firebase.json` already points Hosting at `dist/`; you do not need to run `firebase init` or overwrite it.

1. Open a terminal in this project folder.
2. Build the latest source and log in:

```bash
npm run build
npx firebase-tools login
```

3. Find your **Project ID** under Firebase Console → Project settings → General. Deploy to that project:

```bash
npx firebase-tools deploy --only hosting --project YOUR_PROJECT_ID
```

Replace `YOUR_PROJECT_ID` with the actual ID, not the display name or database URL. Firebase prints the live Hosting URL after deployment. If this project already hosts a different website, use a separate Firebase project or Hosting site rather than replacing that site.

The ZIP also includes a prebuilt `dist/` directory. Rebuild after changing anything in `web/`.

## Optional: Firebase Realtime Database drafts

This is optional. Cover creation, previews, file merging, compression and downloads work immediately without Firebase credentials. No Firebase Storage configuration is used anywhere.

To enable the **Save / Restore cloud draft** controls:

1. In your Firebase project, enable Authentication → Sign-in method → Anonymous.
2. Create or open Realtime Database and copy its exact HTTPS URL.
3. Register a Web App under Project settings to get its public Firebase `apiKey`.
4. Set these values in `web/config.js`:

```js
firebase: {
  enabled: true,
  apiKey: 'YOUR_FIREBASE_WEB_API_KEY',
  databaseURL: 'https://YOUR_EXACT_DATABASE_URL',
}
```

5. Add the `coverDrafts` rules from `database.rules.json` to Realtime Database → Rules. Each anonymous user can access only their own draft. If your database already serves another application, merge the `coverDrafts` branch into your existing rules; **do not replace your existing rules wholesale**. Root-level public read/write permissions would override the privacy intended by the new branch, so review the combined rules.
6. Rebuild and deploy Hosting.

The cloud record contains only the form fields (including assignmentNo and the boolean showAssignmentNo), selected template, quality setting and timestamp. Existing version 1 drafts remain compatible. When upgrading an existing deployment with cloud drafts enabled, merge the updated field rules from database.rules.json before enabling the new inputs. Files, PDF bytes and images are never sent to the database. An anonymous identity is retained in the current browser; it is not a cross-device account. Clearing browser data loses that identity. Cloud failures are shown and do not disable local downloads.

## Practical limits

- Supported assignment uploads: JPG, PNG, WebP and unlocked PDFs.
- Maximum 40 MB per file, 150 MB of unique source files, and 60 assignment pages plus the cover. On low-memory phones use smaller batches and scans.
- Enter cover details in English. Unsupported characters produce a clear message rather than being silently removed.
- Draft fields are saved locally; uploaded files must be selected again after reloading.
- The university logo retains the resolution provided in the original document.
- Original layout and artwork are preserved, including the bridge background in template 8. Review your chosen design for readability before submission.
